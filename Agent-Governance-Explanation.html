Architecture: governed agentic ranking

The system routes a user query through retrieval, contract intelligence, policy ranking, mission repair, governance, execution, and cost/value analysis.

Why this is unique

CORTEX is different because it does not treat every query as the same ranking problem. It first decides whether the query deserves intervention, then chooses the lowest-risk route that still solves the user’s shopping intent.

Traditional search / reranking
Retrieve candidates
Rank by relevance / behavior proxy
May over-focus on popular items
May miss mission-completion needs
Same style of ranking for narrow and broad queries
CORTEX governed ranking

The agents and what each one owns

CORTEX is intentionally decomposed into specialized agents. Each agent owns a decision boundary and produces traceable artifacts.

Intent / Contract Agent

Turns a query into a structured search contract. It captures product type, brand preferences, quality signals, price sensitivity, and ranking weights.

Retrieval Agent

Retrieves a candidate pool using TF-IDF or semantic retrieval. This is the candidate stage before policy, repair, and governance intervene.

Filtering Agent

Applies contract-aware candidate filtering so the downstream policy does not rank clearly misaligned products too highly.

Policy Ranking Agent

Applies policy ranking and slate Q-learning actions. It balances relevance, rating, diversity, and contract priority.

Mission Agent

Detects broad compound queries like “beach vacation packing list” or “new apartment kitchen setup,” where the user needs a multi-category mission slate.

Mission Repair Loop

Finds missing sub-intents and adds useful items only when guardrails accept them. This prevents both under-coverage and over-repair.

Critic / Verifier

Reviews the slate for weak coverage, irrelevant items, high risk, or likely failure modes. It acts like a quality-control agent.

Governance Agent

The top-level brain. It decides whether to preserve baseline, repair, rerank, send to critic, or block repair for narrow branded queries.

Cost / Value Agent

Converts route mix and execution cost into scenario-based business analysis: monthly cost, scenario value, net value, and break-even thresholds.

Governance agent: how the “brain” works

The Governance Agent is what makes CORTEX agentic instead of merely procedural. It decides whether the system should intervene at all.

Inputs

  • Query token count and query type
  • Brand specificity score
  • Compound intent and mission likelihood
  • Strict repair acceptance/rejection signals
  • Coverage gap and repair risk
  • Behavior-aware rescue and exploration signals
  • Critic need score

Routes

  • BASELINE_ONLY — preserve safe baseline
  • MISSION_REPAIR — broaden mission coverage
  • STRICT_REPAIR — repair only with accepted candidates
  • BEHAVIOR_AWARE_RERANK — rerank with policy signals
  • CRITIC_REVIEW — send to critic before trusting repair
  • REJECT_REPAIR_NARROW_QUERY — block over-expansion

The math behind the policy layer

CORTEX uses interpretable scoring and routing formulas rather than pretending to have real click labels when it does not.

Governance decision score

mission_likelihood = f(query_terms, mission_keywords, token_count, brand_penalty)
repair_risk = 0.45·rejection_rate + 0.30·narrow_query + 0.15·no_accepted_repairs
critic_need = 0.40·coverage_gap + 0.35·repair_risk + rejection_bonus + low_confidence_bonus

The route is selected using thresholds over these signals. Narrow branded queries are blocked from aggressive repair; broad mission queries are routed to repair and behavior-aware reranking.

Behavior-aware policy scoring

final_policy_score = α·behavior_proxy + β·mission_stage + γ·coverage_contribution
+ δ·cold_start_rescue + ε·exploration_bonus − λ·risk_penalty

This prevents the system from becoming purely click-greedy. A useful low-evidence item can survive if it helps complete the mission.

Slate reward

SlateReward@K = Σi=1..K discount(i) · quality(labeli)
quality(E)=1.0, quality(S)=0.75, quality(C)=0.55, quality(I)=0

Reward is used for prototype policy learning and evaluation on ESCI labels. It is not presented as production CTR or purchase lift.

Cost vs value

monthly_cost = 30 · daily_queries · E[cost_per_query(route)]
monthly_value = 30 · daily_queries · E[value_per_query(route, scenario)]
net_value = monthly_value − monthly_cost
value_to_cost = monthly_value / monthly_cost

These are configurable assumptions for business-case planning, not measured production revenue.

The implementation is modular: governance decides, the runner executes, the scalable evaluator measures, and the cost/value analyzer frames the business case.

Governance route selection

def choose_route_and_decision(signals): if signals.query_type == "narrow_branded_product_query": return "REJECT_REPAIR_NARROW_QUERY", "REJECT_REPAIR_USE_BASELINE" if signals.critic_need_score >= 0.70: return "CRITIC_REVIEW", "SEND_TO_CRITIC_REVIEW" if signals.strict_accepted_repair_rows > 0 and signals.strict_rejected_repair_rows > 0: return "STRICT_REPAIR", "RUN_STRICT_REPAIR_AND_BEHAVIOR_AWARE" if signals.mission_likelihood_score >= 0.65: return "BEHAVIOR_AWARE_RERANK", "RUN_MISSION_REPAIR_AND_BEHAVIOR_AWARE" return "BASELINE_ONLY", "USE_BASELINE_ONLY"
