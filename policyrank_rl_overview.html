Advanced System Design Document

PolicyRank-RL: CORTEX Engine

An agentic, reinforcement-learning-driven meta-ranking engine for e-commerce search that learns how to generate, mutate, validate, compile, and execute search contracts into optimized product-result slates.

CORTEX = Contract-Oriented Reinforcement for Task-Executable Search

Search Contracts Contract Arena Contract Mutation RL Slate Q-Learning Multi-Agent Diversification Counterfactual Policy Tournament Reward + Regret Engine

1. What CORTEX is trying to achieve

PolicyRank-RL: CORTEX Engine is designed to solve a difficult search problem: users express intent in a short, vague query, but the search engine must decide how to balance relevance, price, quality, personalization, novelty, and diversity. A normal ranker compresses all of this into a score. CORTEX makes the decision process explicit and learnable.

Main idea: CORTEX does not only learn how to rank products. It learns how to create and improve the rules that control ranking for each search context.

The key innovation is the search contract. A contract is a structured, executable agreement that says what the user wants, what the ranker should optimize, what guardrails must be respected, and how success should be measured. CORTEX then uses RL to choose or mutate the best contract execution strategy.

2. The full end-to-end flow

The system begins with a user query and ends with a learning update. The full design has an agentic planning layer, a retrieval layer, an RL policy layer, a policy compiler, a multi-agent slate builder, and a reward/regret engine.

Layer A — User intent and contract generation
1. User QueryExample: “cheap wireless headphones” or “best bathroom fan”.
2. Intent Parser AgentExtracts category, price sensitivity, quality intent, ambiguity, and key constraints.
3. Contract ArenaMultiple specialized agents generate competing search contracts.
4. Constitution CriticValidates guardrails, prevents unsafe or irrelevant ranking behavior.
5. Final Candidate ContractsValidated contracts become executable candidates for ranking.
↓
Layer B — Retrieval and counterfactual evaluation
6. Product RetrievalTF-IDF, semantic retrieval, and later FAISS return candidate products.
7. Candidate Feature BuilderBuilds retrieval score, semantic score, ESCI score, rating score, diversity features.
8. Policy TournamentEach contract is compiled and evaluated offline using ESCI reward.
9. Regret EstimatorCompares chosen contract reward to best counterfactual reward.
10. Tournament WinnerBest contract/policy candidate is selected or blended.
↓
Layer C — RL contract execution and slate construction
11. Contract State EncoderTurns contract + retrieval confidence + user profile into RL state.
12. CORTEX RL CoreChooses contract action: select, mutate, repair, blend, or explore.
13. Policy CompilerTransforms selected contract/action into executable ranking weights.
14. Rank-Position AgentsBuild final top-k slate position by position with diversity awareness.
15. Reward + LearningCompute reward/regret and update Q-values, mutation values, and dashboard.

3. What a search contract means in CORTEX

A search contract is the central object in CORTEX. It is not just a prompt and not just an explanation. It is an executable control object that can be validated, compiled, scored, compared, mutated, and optimized.

SearchContract = { contract_id: string, source_agent: "relevance_agent" | "price_agent" | "quality_agent" | "diversity_agent" | "exploration_agent", query: string, intent: { product_type: string, category: string, price_sensitivity: "low" | "medium" | "high", quality_preference: "low" | "medium" | "high", ambiguity_level: "low" | "medium" | "high", important_terms: list[string] }, objective: string, ranking_weights: { lexical: float, semantic: float, esci_relevance: float, price: float, rating: float, diversity: float, exploration: float }, guardrails: list[string], reward_definition: string, explanation: string }
Contract

What should happen?

Prefer exact headphone matches, include affordable options, avoid irrelevant cheap electronics, and maintain minimum quality.

Policy

How is it executed?

Convert the contract into weights over semantic score, lexical score, ESCI score, price, rating, diversity, and exploration.

7. CORTEX RL architecture in detail

CORTEX has three RL layers. The first is already implemented in simple form. The second and third are the advanced upgrades that make the system significantly more novel.

RL Layer 1

Slate Q-Learning

Learns which ranking compiler strategy works for each contract state.

RL Layer 2

Contract Mutation RL

Learns how to edit contracts to improve slate reward.

RL Layer 3

Counterfactual Regret RL

Evaluates multiple contracts offline and learns to minimize regret.

7.1 State space

The RL state is a compact representation of the search context. It is built from the contract, retrieval confidence, and optionally user profile.

s = Φ(contract, retrieval_confidence, user_profile, query_ambiguity, slate_diagnostics)
Example state: electronics_high_price_sensitivity_medium_quality_low_ambiguity_high_confidence State features: - detected category - product type - price sensitivity - quality preference - ambiguity level - retrieval confidence bucket - exact-match availability - duplicate-risk score - user persona

7.2 Action space

In the current implementation, actions are ranking compiler strategies. In CORTEX, actions become more powerful: the RL agent can select, mutate, repair, blend, or explore contracts.

Action typeExample actionEffect
Compiler selectionsemantic_heavyIncrease weight of semantic similarity.
Contract mutationincrease_esci_weightMake exact relevance more important.
Guardrail insertionadd_no_irrelevant_top3_rulePrevent irrelevant items from top results.
Diversity repairincrease_diversity_weightReduce duplicate-looking results.
Exploration actionallocate_substitute_slotAllow one controlled substitute/complement result.
Contract blendblend_relevance_and_priceCombine outputs of multiple contract agents.

7.3 Q-learning update

Q(s,a) ← Q(s,a) + α [ r + γ maxa′ Q(s′,a′) − Q(s,a) ]

Here, s is the contract state, a is a contract/policy action, and r is the final slate reward. The system learns which action has the highest expected value for each search context.

7.4 Contract mutation RL

Contract mutation is the proposed core novelty. Instead of learning only which policy to pick, CORTEX learns how to edit the contract itself.

C′ = Mutate(C, amutation)
rmutation = SlateReward(C′) − SlateReward(C)

If increasing diversity improves the slate, the mutation receives positive reward. If it hurts exact relevance, it receives negative reward. Over time, CORTEX learns which edits help under which contract states.

7.5 Counterfactual policy tournament

Because ESCI provides offline labels, CORTEX can evaluate multiple contracts without showing all of them to a real user. This is a powerful offline RL trick.

C* = argmaxCᵢ ∈ Arena SlateReward(Slate(Cᵢ))
Regret(Cchosen) = Reward(C*) − Reward(Cchosen)

The dashboard can show not only the reward of the chosen contract, but also how much reward was lost compared with the best counterfactual contract.

7.6 Final ranking score

Score(p | q, C, a) = wlexL(p) + wsemS(p) + wesciE(p) + wpriceP(p) + wratingR(p) + wdivD(p) + wexpX(p)
TermMeaning
L(p)Lexical retrieval score, such as TF-IDF.
S(p)Semantic embedding similarity.
E(p)ESCI relevance score.
P(p)Price/affordability score.
R(p)Rating or quality score.
D(p)Diversity score against selected slate prefix.

8. Multi-agent slate construction

Search users do not consume one product in isolation. They scan a page. That page is a slate. CORTEX treats slate construction as a cooperative multi-agent problem.

AgentScore(p, i) = λrel,i · Relevance(p) + λdiv,i · Diversity(p, S<i) + λpolicy · PolicyScore(p)
Diversity(p, S<i) = 1 − maxs ∈ S<i Similarity(p, s)
Position agentRoleOptimization behavior
Rank-1 AgentSelects first result.Strongest relevance and policy score.
Rank-2 AgentSelects second result.Still high relevance, but avoids being a near-duplicate of rank 1.
Rank-3 to Rank-K AgentsComplete the slate.Balance exactness, substitutes, diversity, and contract satisfaction.
Current implementation: We use a greedy cooperative proxy where each rank-position worker chooses the best remaining product based on relevance, policy score, and diversity. A later research-grade version can use document-as-agent MARL with value decomposition.

9. Reward architecture

Reward is not just click/no-click. CORTEX reward combines relevance, simulated click behavior, contract satisfaction, diversity, and regret.

ItemReward(p) = 0.70 · ESCI(p) + 0.30 · ClickReward(p)
SlateReward@K = [Σi=1..K position_weight(i) · ItemReward(pi)] / [Σi=1..K position_weight(i)]
position_weight(i) = 1 / i
FinalReward = β₁·SlateReward + β₂·Diversity@K + β₃·ContractSatisfaction − β₄·IrrelevantPenalty − β₅·Regret

This prevents the system from optimizing a shallow signal. For example, it should not rank a cheap irrelevant product high just because the price contract says affordability matters.

15. Final pitch

PolicyRank-RL: CORTEX Engine is an agentic meta-ranking framework for e-commerce search. It converts natural-language shopping queries into executable search contracts, lets specialized contract agents compete, validates those contracts with guardrails, evaluates them through counterfactual slate tournaments, uses reinforcement learning to select and mutate contract strategies, compiles the winning contract into a ranking policy, and uses multi-agent workers to build a diversified result slate. The system learns from ESCI-based reward, simulated user feedback, slate reward, and regret.

One-liner: CORTEX learns how to turn user intent into executable ranking contracts, then improves those contracts through reinforcement learning and multi-agent search-page construction.
